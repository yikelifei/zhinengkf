# 微信客服知识库与对话语气说明（2026-08）

## 结论

本次把 9 份微信客服记录中的重复场景整理为 18 条可导入知识，重点覆盖：售前预算与选品、礼盒搭配、Logo/卡片设计、议价下单、加急交期、物流跟进和破损少件售后。

知识库导入文件：`wechat-service-knowledge-2026-08.json`。

这些条目是“脱敏待复核版”，不会自动进入可回复状态。历史聊天中的价格、库存、运费、交期、赠品和商品参数都没有被固化为长期事实，使用时必须读取当前商品库或转人工核实。

## 数据范围与限制

- 来源：9 份 Markdown 微信聊天导出，共 717 条消息。
- 原文件为 UTF-8，整理时已显式按 UTF-8 读取。
- 81 条语音消息没有转写。
- 102 张图片、8 个文件、2 个视频没有读取其业务内容。
- 客户姓名、微信号、电话、详细地址、物流单号、付款码和附件标识均不进入知识库。
- 因附件和语音未完整解析，本轮适合沉淀“流程、语气、追问方式和风险边界”，不适合沉淀某个商品的固定参数与价格。

## 推荐对话语气

整体语气是：熟悉但不轻浮，简短但不敷衍，温和且有明确下一步。

一轮回复建议采用这个顺序：

1. 承接：先回应客户的需求或情绪。
2. 判断：说清现在能确认什么、还缺什么。
3. 动作：给方案或说明正在核实的动作。
4. 闭环：写明谁还需做什么，以及何时回复。

推荐用法：

- “收到，我来帮您核对。”
- “明白，超预算就不硬推。”
- “可以调整，我先确认库存、价差和装盒效果。”
- “这件事我来跟进，今天 16:00 前给您结果。”
- “目前只能确认已经出库，到货时间还要以物流扫描为准。”

谨慎使用：

- “亲”“姐”：熟客可以偶尔使用一次，新客默认用“您”。
- “～”“[爱心]”：成交前的轻松场景可少量使用；投诉、退款、付款和交期争议不用。
- “最低价”“一定到”“今天肯定发”：只有系统或人工审批有明确证据时才能说，否则改为可验证的事实和下一次更新时间。

不建议使用：

- 只有“好滴”“收到”“可以的亲”，没有下一步。
- “不行不行”“做不了”“你只需要看好不好看”这类容易产生压迫感的表达。
- 向客户解释员工私事、利润太低、主管不批、走个人账户等内部信息。
- 未核实就说“图上什么样，收到就什么样”。

## 高频场景的自然话术

| 客户常见说法 | 推荐回复 |
| --- | --- |
| “这个多少？” | “可以，我先按您的预算筛合适的。大概需要多少份、每份预算多少、什么时间使用？” |
| “还是超预算。” | “明白，超预算就不硬推。我按您的上限重新搭配，您更想保留实用性、包装效果，还是定制卡片？” |
| “里面有什么？什么材质？” | “我把内含、材质、尺寸和实拍一起给您。稍等我先核对当前商品资料，避免说错。” |
| “这个能换吗？” | “可以调整，我先确认替换品的库存、价差、尺寸和装盒效果，再把新清单和总价一次发您确认。” |
| “包装不好看。” | “包装可以换。您更看重颜值、预算，还是方便分发？我按这个方向给您两个可落地方案。” |
| “老客户了，再便宜点。” | “明白，老客户我会尽量帮您争取。当前能确认的是这个价格；如果还要调整，我先申请，确认后再回复您。” |
| “今天一定要发。” | “我先核实库存、制作和出库节点。今天能否发出，我会在 14:00 前给您明确结果，未确认前不先保证。” |
| “都到哪里了？” | “我现在逐个核对包裹，稍后给您一份已签收、派送中和异常待查的清单。” |
| “有几个坏了。” | “抱歉给您添麻烦了，我来负责跟进。请发破损照片、外包装和面单，我核实后给您处理方案和时间。” |
| “有两个东西没收到。” | “收到，我先核对装箱记录和分包物流。您先不用反复找，我在约定时间前给您明确结果。” |

## 变量与事实使用规则

以下变量只能在读取订单、商品库、仓库或物流结果后填入：

- `{单价}`、`{总价}`、`{已核实价格或优惠}`
- `{库存}`、`{制作节点}`、`{发货时间}`、`{物流时效}`
- `{产品组合}`、`{数量}`、`{包裹数}`
- `{明确时间}`、`{回复时间}`

如果数据源没有返回值，客服应该说“我正在核实”，不能把旧聊天内容或常识猜测填进去。

## 导入与复核建议

1. 先使用项目的知识库“导入预览”检查 18 条记录和 Agent 归属。
2. 由业务负责人复核优惠权限、付款渠道、交期承诺、售后政策和禁用表达。
3. 复核通过后，将条目状态由 `review` 改为 `ready`。
4. 用真实但脱敏的测试问题验证召回，重点测试“价格”“预算”“Logo”“加急”“物流”“破损”“少件”等关键词。
5. 每次商品价格、库存或售后政策变化时更新业务系统，不要在这份话术知识中维护易变数据。
