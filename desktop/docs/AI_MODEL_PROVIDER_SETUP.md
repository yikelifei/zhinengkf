# 大模型供应商接入

桌面端的“大模型中心”预置 18 家供应商。操作员打开 `/settings/ai-models`，选择供应商、粘贴 API Key 并点击“保存并启用”即可；默认模型、接口地址、请求协议和路由层级已经随应用提供，无需改代码或 YAML。

## 已预置供应商

国内：智谱 GLM、DeepSeek、阿里云百炼 Qwen、硅基流动、火山方舟 / 豆包、Moonshot / Kimi、百度千帆 / 文心、腾讯混元、MiniMax、阶跃星辰。

海外与聚合：OpenAI、Anthropic Claude、Google Gemini、xAI Grok、Groq、Mistral AI、Together AI、OpenRouter。

Anthropic 使用原生 Messages API；其余预设使用各厂商官方提供的 OpenAI 兼容 Chat Completions 接口。没有密钥的供应商保持停用，不会参与请求，也不会影响已有的真熙 AI 或其他现有供应商。

## 密钥和运行方式

- 密钥只由受信任操作员保存到项目根目录 `.env`，文件写入采用私有权限和原子替换。
- 状态接口只返回 `apiKeyConfigured`，不会回传或在界面显示密钥原文。
- 保存后同步更新当前 API 进程环境，供应商立即加入快速或高质量路由，无需重启。
- “连通性探测”会向已经配置的供应商发送一次最小文本请求，可能产生极少量调用费用；普通保存不会主动调用供应商。
- 每个供应商保留独立启停开关。停用不会删除密钥，重新启用时可以不重复粘贴。

## 自适应切换与响应速度

- 客户的短问句、普通咨询优先进入快速模型链；交易、投诉、金额、交付等复杂场景只进入高质量模型链。
- 路由器记录当前进程内每家供应商的平均耗时、成功率和连续失败次数，并在下一次请求前自动重排同层模型。
- 一个供应商连续失败两次后会自动熔断冷却；冷却期间跳过它并切换下一家，恢复成功后重新加入排序。
- 有总响应预算时，路由器会结合已学习耗时判断后备模型能否在剩余时间完成；聊天快路径硬上限为 4.5 秒，人工生成建议硬上限为 8 秒。
- 每次请求最多尝试少量排名靠前的模型，避免配置很多密钥后把十几家供应商串行跑一遍。
- 大模型中心显示当前实际快速/高质量顺序、平均响应时间、成功率和熔断状态。运行指标仅保存在当前服务进程内，重启后重新学习。

## 不属于“只填密钥”的接入

Azure OpenAI、AWS Bedrock、Google Vertex AI，以及企业自建或本地模型通常还需要部署名、区域、项目、服务账号或自定义地址，无法诚实地简化为一个 Key。系统保留 `custom_api_1`、`custom_api_2` 等自定义通道承载这类接入；确认具体平台参数后再配置，避免猜测接口。
