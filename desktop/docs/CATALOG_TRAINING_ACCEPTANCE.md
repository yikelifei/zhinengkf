# 商品库与知识库运营验收状态

本文件用于说明当前商品库、知识库能交付到什么程度，以及上线前还需要补哪些真实运营数据。页面展示必须来自真实接口或规则审计，不伪造已付款、已发货、已训练等业务状态。

## 商品库运营验收

| 能力 | 当前闭环 | 验收入口 | 用户需要补充 |
| --- | --- | --- | --- |
| 查看商品 | 读取 `/catalog/skus`，拒绝客户端内置假商品降级 | `/catalog/products` | 真实 SKU 名称、分类、价格、库存 |
| 导入商品 | 文本/文件先预览和审计，再人工确认批量写入 | `/catalog/import` | 按导入模板整理真实供应商商品表 |
| 审计商品 | 规则层检查图片、库存、利润、规格、组合和报价前置风险 | `/catalog/audit` | 修正阻断项，不把 demo 图当正式商品图 |
| 修复商品 | 审计生成修复队列，单个 SKU 二次确认后提交批量更新 | `/catalog/repair` | 真实库存、供应商、交期、主图和多角度图 |
| 搭配推荐 | 调用现有 `/catalog/bundle/recommend`，只做推荐试算 | `/catalog/bundles` | 真实预算带、场景标签、可售组合边界 |
| 报价前置 | 使用 `commercialReadiness.canAutoQuote/canSubmitDesign` 判断是否可进入报价 | `/catalog/audit`、`/sales/quotes` | 销售侧仍需真实客户、报价确认和订单流程 |

## 知识库运营验收

| 能力 | 当前闭环 | 验收入口 | 用户需要补充 |
| --- | --- | --- | --- |
| SOP 覆盖 | 读取 `/training/knowledge`，拆分 starter SOP 与自定义知识 | `/training/overview` | 继续补品牌、报价、物流、售后等自有 SOP |
| 按 Agent 查看 | 概览展示每个 Agent 的知识条目数量和示例标题 | `/training/overview` | 给真实岗位 Agent 绑定清晰场景和责任 |
| 按场景查看 | 运营验收面板统计知识标签和高频标签 | `/training/overview` | 真实聊天和纠错条目需要补标签 |
| starter vs 自定义 | starter_knowledge 单独计数，自定义沉淀单独计数 | `/training/overview` | 把真实客服话术沉淀为自定义知识 |
| 训练/纠错入口 | 从概览跳转到导入、复核、技能建议，写入仍需人工确认 | `/training/import`、`/training/review`、`/training/skills` | 导入真实聊天记录并复核风险样本 |

## 上线注意

- 商品库就绪不代表已付款或已发货；付款、订单和物流状态必须由销售/订单/发货模块确认。
- 知识库有条目不代表已训练完成；样本复核和技能应用必须走训练模块的人工确认。
- 图片生成相关任务仍必须调用臻希 AI，不在商品库或知识库模块接入其他图片生成后端。
