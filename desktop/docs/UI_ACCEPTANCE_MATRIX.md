# 前端页面职责与上线验收矩阵

本文档是桌面端工作台模块化改造的上线合同。页面、按钮和数据请求都必须遵守这里的边界；新增功能时先选择所属页面，不能继续向全局工作台堆叠。

## 1. 页面设计原则

1. 一个 URL 只承载一个完整用户目标，不按“一个按钮一个页面”机械拆分。
2. 页面内可以包含完成同一目标所需的步骤；跨业务域动作只展示摘要并导航到目标页面。
3. DOM 只挂载当前页面；页面卸载时必须停止本页轮询、请求和全局监听。
4. 每页独立处理 `loading / empty / error / permission denied / ready`，API 失败不得伪装成空列表或演示数据。
5. 页面头最多一个主操作。批量、危险、付款、发送、停用等动作必须给出范围、身份、后果和确认。
6. 生产模式不得显示演示任务、错误窗口、失败演示、超时演示等开发工具。

信息架构验收：`sales-center` 只归属 `/sales/*`，`automation-center` 只归属四个 `/automation/*`，`notice-center` 只归属 `/notifications`。侧栏分别显示“销售管理”和“自动化管理”；销售模块导航不显示仅用于流程选择的 `/sales/actions`。

## 3. 按钮合同

- 每个业务按钮必须有稳定的 `data-action-id`，名称使用 `<domain>.<entity>.<verb>`。
- 按钮文案必须描述结果，例如“发送报价”不能写成含糊的“处理”。
- 禁用按钮必须同时提供可见原因或可访问说明，不能只改变颜色。
- 跨模块按钮只调用路由，不得在当前页偷偷执行目标模块动作。
- 发送、付款、停用、取消、驳回、批量修改必须显示确认范围和身份。
- 正在执行时只锁定当前动作或当前实体，不得用全局 `busy` 禁用整个工作台。
- 不确定投递、身份不一致、权限未确认和配置缺失均按 fail-closed 处理。

## 4. 代码模块合同

每个 feature 目录至少包含：

```text
features/<domain>/
  api.ts              # 只封装本域现有接口
  model.ts            # 页面模型和状态类型
  selectors.ts        # 纯派生逻辑，可独立测试
  use-*-controller.ts # 本页请求、动作和清理
  *-feature-page.tsx  # 页面组合层
  components/         # 纯展示积木
  *.module.css        # 本域样式
```

约束：

- `app/**/page.tsx` 直接导入且只导入一个归属 feature，或执行一个明确重定向；业务逻辑留在 feature，公共壳由 `app/feature-route-shell.tsx` 提供。
- feature 不得直接修改共享导航、全局 token、旧 `page.tsx` 或 `globals.css`。
- 共享 Context 只保存账号、会话、客户与操作者身份，不保存跨域业务数据。
- 每个 controller 只加载本页接口，并在卸载时取消或忽略过期请求。
- 新代码不得继续向未引用的 `legacy-workbench.tsx` 添加演示回退；新路由不得重新引入旧 `globals.css`。

## 5. 响应式与可访问性

- 验收宽度：1440、1280、1024、760 和 390px。
- 390px 不允许横向滚动、固定头遮挡、底部导航覆盖主操作或不可达按钮。
- 键盘必须可完成导航、筛选、确认和取消；弹层支持 Escape 并恢复焦点。
- 每页只有一个 `h1` 和一个主 `main` landmark；表格在移动端必须保持字段语义。
- 动画遵守 `prefers-reduced-motion`。

## 6. 上线门禁

每个分支至少通过：

1. 模块定向测试和现有相关契约测试。
2. TypeScript 检查和 Next 生产构建。
3. `git diff --check`。
4. 桌面与 390px 真浏览器检查：URL、标题、非空、无框架错误层、控制台、截图、一个核心交互。
5. 深链接、刷新、前进/后退、错误态、空态、权限态和长文本。
6. 证明切页后本模块轮询和事件监听已停止。

最终集成按 `router foundation -> feature branches -> route cutover -> browser QA` 顺序进行，禁止把主脏工作区当作集成分支。
