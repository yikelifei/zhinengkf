# 企业微信一体化产品范围

更新时间：2026-08-19

## 产品目标

本项目不是“调用几个企业微信接口”的演示，而是一套从获客、接待、方案、审核、发送、成交到长期客户运营的服务系统。API 接入必须同时具备：

1. 用户可找到并完成的产品入口。
2. 企业微信官方 API 或官方回调实现。
3. 角色权限、显式确认、幂等和审计。
4. 异常状态、补偿路径和人工接管。
5. 自动化测试、真实企业只读验证和客户手机验收边界。

## 范围判定

纳入范围：微信客服、客户联系、客户群、企业成员目录、素材、商品图册、统计、获客助手、欢迎语、群发、朋友圈、敏感词与继承转接。它们直接支撑本项目的客户接待、销售、长期服务和运营自动化。

不纳入范围：邮件、会议、打卡、审批、教育、政务等与智能客服及销售运营无直接关系的企业微信 API。若未来产品增加对应业务，再进入范围。

官方文档根目录共识别 735 篇服务端 API 文档。自动审计已读取 337 篇；其余 398 篇当前被官网 HTTP 429/人机验证阻断，监理任务会限速续跑。未读到正文的接口不得靠猜测标记为完成。

## 交付顺序

### P0 日常运营闭环

- 客服账号、接待人员、成员目录。
- 客户入口、真实收发、服务状态、长期客户升级。
- 权限、幂等、审计、异步失败和人工接管。

### P1 经营数据与客户资产

- 客服统计和接待人员统计。
- 客户列表、详情、备注、标签、客户群和群成员。
- 本地客户/订单/报价与企业微信客户身份对账。

### P2 自动触达与内容运营

- 欢迎语、群欢迎语、群发、朋友圈。
- 每项触达都必须经过人群预览、频控、审批、发送回执和失败补偿。

### P3 商品、获客与组织风控

- 商品图册和本地商品库同步。
- 获客助手链接、事件和转化统计。
- 敏感词、在职转接、离职继承和待处理异常。

## 验收规则

1. `本地测试通过`：只能证明代码契约和页面行为。
2. `官方 API 返回 errcode=0`：证明企业微信接受请求，不证明客户手机已显示。
3. `企业后台对账一致`：证明配置或数据已在企业侧生效。
4. `客户手机实收`：必须记录客户、消息类型、发送时间、企业微信回执和客户确认。
5. 写操作验收不得自动改动线上账号、成员、群发或朋友圈，必须由有权限人员明确确认。

## 监理要求

- 每 4 小时续跑官方文档审计，优先微信客服与客户联系。
- 新增功能必须同时更新能力地图、接口测试、产品入口和真实验收记录。
- 不显示 Secret、access token、事件 code 或客户敏感信息。
- 不得把模拟数据、端口健康、HTTP 200 或截图当作客户手机送达证明。
